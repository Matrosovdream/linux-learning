# 04 — The Filesystem Hierarchy

## Goals
- Understand that Linux has one single tree rooted at `/` (no drive letters).
- Know the purpose of the major top-level directories — especially the ones web devs touch.
- Be able to guess *where* a config, log, or binary lives before searching for it.

## Concepts
- **One tree, rooted at `/`.** Unlike Windows (`C:`, `D:`), Linux has a single hierarchy starting at `/` (the **root directory**). Everything — disks, devices, even other mounted filesystems — hangs somewhere off `/`.
- **Absolute vs relative paths.** Absolute paths start at `/` (`/etc/nginx/nginx.conf`); relative paths start from your current directory (`nginx/nginx.conf`). `.` = here, `..` = parent, `~` = your home directory.
- **The Filesystem Hierarchy Standard (FHS)** defines what each top-level directory is for. The ones that matter most:
  - **`/etc`** — **system-wide configuration** (text files). Web dev gold: `/etc/nginx/`, `/etc/hosts`, `/etc/ssh/`, `/etc/passwd`. If you're configuring software, it's almost always here.
  - **`/var`** — **variable data** that changes at runtime: `/var/log` (logs!), `/var/lib` (databases, app state), `/var/www` (traditional web root), `/var/cache`.
  - **`/usr`** — installed software: `/usr/bin` (most programs), `/usr/lib` (libraries), `/usr/share` (docs, data). Think "the OS's read-only program files."
  - **`/bin`, `/sbin`** — essential system binaries (`sbin` = admin tools). On modern Debian these are symlinks into `/usr/bin`.
  - **`/home`** — per-user home directories (`/home/alice`). Your personal files, dotfiles, SSH keys live here. (root's home is `/root`, not under `/home`.)
  - **`/tmp`** — temporary scratch, world-writable, **wiped on reboot**. Never store anything you want to keep.
  - **`/opt`** — optional/third-party software installed as a self-contained bundle.
  - **`/proc` and `/sys`** — **virtual** filesystems generated by the kernel. Not real files on disk — they expose live process and hardware info as readable paths (e.g. `/proc/cpuinfo`, `/proc/<pid>/`). This is "everything is a file" in action.
  - **`/dev`** — device files (`/dev/null` the black hole, `/dev/random`, disks like `/dev/sda`).
  - **`/root`** — the root user's home directory.
  - **`/mnt`, `/media`** — mount points for extra/removable filesystems.
- **Where web stuff typically lives:**
  - nginx config → `/etc/nginx/`; nginx logs → `/var/log/nginx/`; static site files → `/var/www/html/` (or wherever you point it).
  - Installed programs → `/usr/bin` (e.g. `which nginx` → `/usr/sbin/nginx`).
  - App data / databases → `/var/lib/...`.
- **`/proc` is a debugging superpower.** `cat /proc/cpuinfo`, `cat /proc/meminfo`, and `/proc/<pid>/environ` let you inspect a running system with plain `cat`. We'll use it in the processes lesson.

## Exercises
1. Run `ls /` and name what each top-level entry is for (check yourself against the list above; ask Claude about any you don't recognize).
2. Explore configs: `ls /etc`, then `cat /etc/hostname` and `cat /etc/hosts`. These are real config files you'll edit later.
3. Explore logs: `ls -l /var/log`. (Your fresh container may have few; that changes once you install services.)
4. Find a program's real location: `which bash`, `which ls`. Note they're under `/usr/bin`.
5. Peek at the virtual filesystem: `cat /proc/cpuinfo | head`, `cat /proc/meminfo | head`, and `cat /proc/uptime`. Ask Claude why these aren't "real" files.
6. Prove `/tmp` vs persistent storage: write `/tmp/throwaway.txt` and a file in your persistent `/work` area, then predict which survives a container rebuild.
7. Practice paths: from `/etc/nginx` (after it exists) you could reach a log with `../../var/log/nginx/access.log`. On paper, convert that relative path to an absolute one.

## Best Practices & Pitfalls
- **Learn `/etc`, `/var`, `/usr` cold.** 90% of web-dev sysadmin work is "edit a config in `/etc`, read a log in `/var/log`, run a binary from `/usr/bin`." If you internalize this, you'll stop guessing.
- **Never rely on `/tmp` for anything lasting.** It's scratch space and may be cleared at any time.
- **Pitfall: confusing `/` (root directory) with `/root` (root user's home) with `root` (the user).** Three different things that share a name.
- **Pitfall: editing files under `/usr` or `/proc`.** `/usr` is package-manager territory (your edits get overwritten on update); `/proc` and `/sys` are kernel-generated (you usually can't or shouldn't hand-edit them).
- **Use `ls -F` or `ls --color`** to tell directories, files, and symlinks apart at a glance — many of `/bin`, `/sbin` are symlinks on Debian.

## Checklist
- [ ] I understand there's one tree starting at `/`, with no drive letters.
- [ ] I can state what `/etc`, `/var`, `/usr`, `/home`, `/tmp`, `/proc` are for.
